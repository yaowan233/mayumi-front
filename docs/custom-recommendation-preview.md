# 定制算法本机预览

页面：http://localhost:3000/recommend

## 登录要求

网页两种推荐方式均需登录。服务端页面和 `/api/recommendations` 独立读取 `uuid` 会话并向 Mayumi `/api/me` 验证，禁止缓存验证响应；不以 Cookie 存在、UID 参数或客户端上下文作为认证依据。匿名/无效会话返回 401，认证服务故障返回 503，均不调用推荐引擎。登录沿用网站现有 osu! OAuth 入口。登录用户仍可查询其他玩家公开 BP，未增加 UID 所有权限制。

仅本机监听的算法预览端口 8001 仍是内部开发入口，不对公网开放；该网页登录校验不替代算法部署时的 API Token 和网络访问控制。

链路：浏览器 → Next.js 同源 `/api/recommendations` → 配置的算法服务：条件发现用 `POST /recommend/custom`，按玩家推荐用 `POST /recommend/personal/jobs` 并轮询任务状态 → 现有推荐数据库。

生产部署须在服务器环境中设置 `CUSTOM_RECOMMENDER_API_URL`，需要鉴权时同时设置 `CUSTOM_RECOMMENDER_API_TOKEN`。算法地址必须能从网页服务器访问；本机 `.env.local` 不随 Git 推送。

网页通过 POST `/api/recommendations` 提交任务，再以 GET `?job=...` 每两秒轮询，避免 CDN 截断长请求。每次请求均验证登录和任务所有者。Next.js 单进程最多 2 个计算任务、16 个保留任务，完成后保留 120 秒以复用重复请求；服务重启会丢失任务，需要重新推荐。当前仅支持常驻单进程部署，不适用于无状态多实例或 serverless。网关轮询限速应允许每用户每两秒一次；原有同步 GET 仅为兼容保留。

## 支持的功能

- 按条件发现使用通用综合排序；按玩家推荐复用现有四模式个性化引擎的画像、风格簇、ACC / PP 估算、可玩性和目标排序，不再用 BP 风格加热度代替完整引擎。不走旧推荐 Top-50 后置筛选。
- 按玩家推荐支持刷分、均衡、突破、风格目标。进入该模式默认星级 0–20、最长 3600 秒、支持的 7 种 Mod，由旧引擎自身的能力、Mod 池和证据门槛进一步筛选；默认仍排除 CTB 转谱。
- 后端先从有效难度缓存获得完整硬条件候选集合，不做通用热度 Top-N 截断；显式传入各模式召回，在风格排序及候选截断前排除不匹配的 map/mod。最终精算星级超出范围仍剔除，不自动放宽条件。
- 个性化卡片保留引擎排序和原始评分，显示预测 ACC / PP、模型或规则来源及整体/簇风格解释。PP 是单次成绩估算，不是账号净 PP 增量，也不保证 FC。无有效持久化玩家画像时返回明确错误，不悄悄退化成通用推荐；本机接口不自动同步新玩家。
- 推荐结果采用原生语义表格，各属性独立成列：星级、Mod、时长、BPM、键数、ACC、PP、评分、BP 样本和风格分项。固定表头，桌面横向滚动时固定谱面列；窄屏在表格内部滚动，保留列对齐。长名称可悬停查看，排序说明默认折叠。不改变算法顺序。
- 条件发现的参考谱、数值软偏好、多样性暂不叠加到个人引擎；个人模式隐藏这些控件，直接传入这些参数也会被拒绝。个性化请求不复用旧无筛选推荐缓存，避免不同筛选条件串用结果。
- 星级、代表 BPM、最长物件跨度、mania 键数、精确 Mod 组合在数据库召回阶段生效。混合选项明确代表 NM/DT/HT 三种，不代表任意 Mod。
- 展开「风格与目标偏好」可设置偏好星级、BPM、物件时长、参考 Beatmap ID 及其 Mod、多样性。
- 登录后可不指定玩家 UID，仅按条件和参考谱面发现谱面。偏好目标须处于硬范围内。
- 默认综合分降序：45% 本地 BP 热度 + 55% 刷分证据；不再偏向星级区间中点。多样性默认为 0，主动开启后可能改变综合分顺序。同分按谱面 ID / Mod 稳定排序。
- 热度为 `log(1+n)/(log(1+n)+3)`；刷分证据为 `mean(1-bp_position/100)*n/(n+20)`。n 为该谱面与精确 Mod 在本地有效 Top100 BP 中的样本数；不是全站游玩次数。小样本折扣避免单条高排位记录占优，无证据记 0，不代表谱面不好。
- 显式设置数值偏好、参考谱或个人画像时，综合证据占 60%，有效偏好分量等权合计占 40%。无数值偏好时，数据库也按同一综合公式召回；有数值偏好时先按目标距离召回，再综合重排。每 Mod 候选数有限。
- 这些是未经离线校准的启发式权重。BP 样本有玩家水平和幸存者偏差，BP 排位仅为刷分证据，不是容易程度、FC 概率或个人净 PP 收益；不显示个人 ACC / PP。
- CTB 默认只召回原生谱，可勾选包含转谱。卡片展示真实封面，元数据缺失或图片加载失败显示占位。
- 算法先读取本地 `.osu` 元数据；缺失时 Next.js 服务端用官方 `/api/v2/beatmaps` 批量补全曲名、作者、难度名和谱面集 ID，复用 `NEXT_PUBLIC_CLIENT_ID` / `CLIENT_SECRET`，不覆盖 Mod 后星级、分数或排序。官方资料：https://osu.ppy.sh/docs/#get-beatmaps
- 元数据使用进程内有界缓存（最多 1000 张，成功 24 小时，官方未返回 5 分钟，请求失败 30 秒）；重启清空。鉴权和批量请求各有 8 秒超时，失败仍返回推荐及官网链接，不会伪造详情。
- 本机 Node 直连官网失败时，可配置服务端 `OSU_METADATA_PROXY_URL`，仅用于官方元数据请求。关闭 TUN 后本机直连已恢复，当前预览不设置代理；生产环境按实际网络配置。
- 条件发现不支持个人刷 PP 目标；两种模式均暂不支持关键词、上架状态筛选，有缓存的未上架谱面可能返回。
- 时长已统一为 Mod 后首尾物件跨度，不是历史官方搜索使用的音频总长。

## 启动

在算法仓库 `C:\Users\57247\Desktop\OSUBeatmapRecommender`：

```powershell
uv run python run_custom_preview.py
```

该入口加载算法仓库原 `.env` 中的数据库连接，仅监听 127.0.0.1:8001。关闭该本机进程的 API 鉴权与 lifespan 预热/缓存表初始化，避免本次预览触发建表或全模式加载；不是生产启动命令，不能改为公网监听。

前端 `.env.local` 设置：

```dotenv
CUSTOM_RECOMMENDER_API_URL=http://127.0.0.1:8001
```

可选服务端 `CUSTOM_RECOMMENDER_API_TOKEN` 配套有鉴权的算法实例；本机入口不需要。原 `RECOMMENDER_API_URL` 保留但此页面不再读取它，避免误用尚未安装新接口的 NAS 服务。

前端运行 `npm run dev`。本次复用原有 3000 端口的 Next.js 开发服务，没有重启用户原服务；算法预览另开在 8001。

# 四模式 embedding 特征筛选

「我的风格参考」默认折叠，首次展开画像或谱面偏好才读取当前玩家 BP 原谱参考值。每项至少 5 条样本，mania 分键数展示。黄色标记仅供参考。「按画像优先推荐 · 清除特征限制」切换到已有个人引擎的 style 目标，显式清除特征硬范围及条件发现偏好，保留基础数值/Mod 条件，mania 选中参考键数；点击更新后生效。不再把全部画像维度一键变成硬条件。每个特征可单独启用参考范围；空结果提供清除特征限制并重试的操作，不静默放宽条件。「本次读取于」不是 BP 更新时间。

默认 UX：进入页面自动请求一次当前登录玩家的推荐（不在每次拖动筛选时请求）。首屏只显示模式、游玩目标、mania 键数与更新按钮；基础筛选、谱面偏好和其他玩家/推荐方式默认折叠。自定义条件以可删除标签展示。修改条件保留上次结果并标明尚未更新，结果列使用实际请求时的模式，不会被未提交的模式选择误标。默认精简表格，可勾选显示更多列；失败可手动重试，取消/切换条件/离开页面会中止旧请求。

UX：mania 键数改为 4K–10K 多选框，可组合如 4K + 7K；全部不选表示不限。所有模式的比例使用双端滑条（1% 步进，支持键盘），实时显示上下限。回到 0–100% 或点击重置会移除该项条件；0–0% 仍严格筛选零值。密度和距离保留数值输入。键数组合由后端 `key_counts` 在召回前执行。

玩家推荐和条件发现均支持「谱面特征筛选」。每项可填最低、最高或单边范围，留空不限；百分比输入 0–100。切换模式清空特征条件，表格展示原谱特征值，缺失显示 `—`。

- osu：滑条占比、跳距 P90、转角变化比例、平均/峰值密度。
- taiko：蓝键、大音符、换色比例、平均/峰值密度。
- CTB：换向、边缘占比、横向跳距 P90、平均/峰值密度。
- mania：LN、多押、LN 重叠比例、平均/峰值密度。

这些特征使用原谱 NM embedding 值（密度也一样），不是 Mod 后值或官方技能评级；CTB 基于原始物件几何近似。星级/BPM/时长仍按 Mod 后值。条件通过 `feature_ranges` 在引擎召回截断前执行，不是对返回列表事后裁剪；保留原有排序。所选特征缺失会排除，不自动放宽。需要新版算法服务，原模型无需重训。
